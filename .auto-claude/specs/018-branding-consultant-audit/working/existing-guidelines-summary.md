## 3. Writing Style Guidelines (Key Rules)

### The 7 Writing Rules

1. **Start with the problem, not the solution**
   - Lead with the challenge/pain point the user faces

2. **Use everyday metaphors for complex concepts**
   - Make technical concepts accessible through familiar comparisons

3. **Employ constructive irony to highlight issues**
   - Use humor strategically to point out problems

4. **Create mental scenes instead of abstractions**
   - Paint vivid pictures rather than abstract statements

5. **Use sentence case (only initial capital)**
   - Example: "How we solved the checkout problem" NOT "How We Solved The Checkout Problem"

6. **Keep paragraphs to 3-4 lines max**
   - Short, digestible content blocks

7. **Use "we" instead of "you should"**
   - Collaborative tone, not prescriptive

## 4. Content Examples (Before/After)

### Example 1: Technical Description

| ❌ DON'T | ✅ DO |
|----------|-------|
| "Implement robust authentication system with JWT tokens" | "We're solving the '3am password reset' problem - when users are locked out and frustrated" |

**Principle**: Start with the human problem, not the technical solution

### Example 2: Results Communication

| ❌ DON'T | ✅ DO |
|----------|-------|
| "Optimized performance metrics" | "Cut payment times by 12%. How? Reduced clicks from 7 to 3. Sometimes the answer isn't complex." |

**Principle**: Be specific, show the "how", and keep it humble

- **Borders**: 4-6px solid black (hard edges)

## 6. Accessibility Requirements (WCAG AA)

- **Skip Links**: Keyboard navigation bypass
- **Touch Targets**: Minimum 48×48px on mobile
- **Reduced Motion**: Respects user preference
- **Focus Indicators**: 4px solid Electric Blue outline
- **Color Contrast**: All colors ≥4.5:1 contrast ratio
